## Reading the user's Telegram and WhatsApp through Social Connect

Social Connect is a hosted MCP server, `social-connect`, at `https://staging.cooposio.com/mcp` (streamable HTTP, OAuth 2.1 with PKCE, dynamic client registration; no token in any file). Add it with `codex mcp add social-connect --url <url>` or `claude mcp add --transport http social-connect <url>`, then sign in (`codex mcp login social-connect`, or `/mcp`): enter an email, type the emailed 6-digit code, approve (the first time, save the recovery code the page shows once). If Telegram is not connected yet, the consent button is "Allow and connect Telegram": scan the QR code with Telegram (Settings → Devices → Link Desktop Device, or tap the `tg://` link on the phone), and the browser returns to the assistant. WhatsApp (beta): `connect_account({provider:"whatsapp"})`; the link opens `/connect/whatsapp`, shown on a computer or second screen (not the same phone), and the user scans it from WhatsApp → Settings → Linked devices → Link a device.

Tools: `connection_status()` first; `connect_account({provider:"telegram"|"whatsapp"})` returns a 30-minute `connect_url` (`/link/cl2.…`, carrying a 2-hour device unlock: a secret, for the account's own human only, never posted publicly or written to files); `list_recent_chats({limit<=20, provider?})` merges both providers unless `provider` is given, each chat with `provider` and a `chat_ref` (`cr1.` Telegram, `wr1.` WhatsApp; pass back unchanged); `read_recent_messages({chat_ref, limit<=30})` returns `{provider, messages, sync?}`, text only, never marks read; on WhatsApp `sync.state:"partial"` means older messages may be missing (it only has what arrived while connected): say so, never claim there are none; `request_reply_approval({chat_ref, text})` creates a pending reply and returns `approval_url`. Nothing is ever sent unless the human approves it in the web app; sending is disabled on staging. Never say a message was sent.

Autonomous agent with its own mailbox (no browser): `GET <web>/api/agent/` describes; `POST <web>/api/agent/signup {email, agent_name}` emails a code; register a public client at `/oauth/register` (redirect `http://127.0.0.1:8976/callback`, auth method `none`); build a PKCE S256 `/authorize` URL with `scope=telegram` and `resource=<web>/mcp`; `POST <web>/api/agent/authorize {email, code, authorize_url, recovery_code?}` returns `redirect_to` with `code` (check `state`); the first time it also returns `recovery_code` once: store it in a secret store, never print it, and send it on every later authorize for that account, else 403 `recovery_code_required` (the emailed code is then used up); exchange at `/oauth/token` with the verifier; call `/mcp`; then `connect_account` and give the link to your human. Keep tokens and the recovery code in a secret store; never print them or the emailed code. The plugin's `scripts/agent-signup.sh` (POSIX sh, curl, openssl) does all of it. An address that belongs to a browser-created account answers 409: that person signs in normally.

Etiquette: read only when the user asked in this conversation; say which chat you open; at most 20 chats and 30 messages per call, start smaller; summarize instead of dumping messages, quote only when asked; do not copy message contents into files or other tools. Show a draft and its `approval_url` once and never pressure the human to approve. "Telegram is not connected. Ask the user to open <url> …": show that link, wait for them, then `connection_status` and retry once. "Rate limit: at most 30 Social Connect calls per minute", "Telegram is rate-limiting this account. Try again in N …" or a sign-in 429: stop, tell the user, retry once after the stated time; never loop. HTTP 401, or "Encryption keys changed; connect this assistant again" on refresh: sign in again. Privacy (Telegram and WhatsApp): "encrypted with a key that only you, and the AI apps you connect, can unlock. We don't keep that key."; WhatsApp: "We connect to WhatsApp only while you're using your assistant. Messages that arrive while you're away are fetched next time, within WhatsApp's limits." WhatsApp is beta. Never say "end-to-end encrypted" or "zero-knowledge".
